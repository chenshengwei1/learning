糖果消消乐项目测试计划

1. 文档目的

本文档用于对糖果消消乐项目（v5）进行功能验证、回归检查和交付验收，覆盖核心玩法、配置能力、状态系统、模式切换、关卡系统与浏览器表现。它适用于开发阶段检测和团队评审阶段确认。

2. 测试目标

  • 棋盘渲染与交互是否正常（点击交换 / 拖拽交换）
  • 直线、田字、斜线规则与最少连消数量是否正确
  • 爆炸规则（cross / screen / blast）、炸弹、围墙、冻结、锁定、冰层是否有效
  • 管理员模式与游戏模式切换、通关目标结算是否正确
  • 配置模板切换、单格编辑、关卡保存与加载是否稳定
  • 初始棋盘、时间限制、步数限制逻辑是否符合预期
  • 棋盘自愈（无初始三连、无解自动洗牌）、局部刷新与页面稳定性

3. 测试范围

功能验证

  • 基础消除 / 连锁响应 / 计分逻辑 / 步数控制 / 时间限制 / 胜负判断
  • 双模式切换 / 提示功能 / 无解自动洗牌

配置验证

  • 预设模板切换 / 自定义棋子 / 初始棋盘 / 爆炸规则配置
  • 配置保存与恢复 / 默认配置回退 / 配置解析稳定性
  • 关卡保存与加载（本地关卡库）

特殊状态与障碍验证

  • locked / frozen / bomb / ice / wall / blank / empty

管理员编辑器验证

  • 单格属性编辑（类型/图案/底色/图案色/移动/冰层/四边围墙）
  • 应用管理员配置与棋盘重建

4. 测试环境

运行环境

  • 浏览器：Chrome、Edge、Firefox 的现代版本
  • 运行方式：直接打开 index.html（或通过 docs/index.html 入口）
  • 依赖项：无额外安装依赖

验收方式

  • 手动交互验证（管理员模式构造场景 + 游戏模式验证）
  • 浏览器控制台检查报错
  • localStorage 检查配置持久化与关卡库（candy_crush_config_v5 / candy_crush_levels_v5）
  • 关键脚本语法检查：node --check game.js

5. 测试用例

TC-01：页面正常加载

目标：页面稳定初始化并展示完整 UI。

步骤：打开 index.html，观察左侧规则面板、中央棋盘、右侧编辑器。

预期：棋盘稳定显示（默认 10×10），分数/步数/连击/目标/时间可见，控制台无脚本错误；加载后棋盘内不存在初始三连。

TC-02：有效交换与消除

目标：相邻棋子合法交换后可形成匹配并消除。

预期：形成 3 连及以上后棋子被移除，分数增加，重力补齐生效，UI 同步更新。

TC-03：无效交换

目标：不构成有效消除的交换不产生错误结果。

预期：操作被拒绝、棋子回弹复位、无错误计分、状态保持一致。

TC-04：点击交换与拖拽交换

目标：两种交互方式均可用。

步骤：①先点击棋子 A 再点击相邻棋子 B 完成交换；②直接按住棋子向相邻方向拖拽超过阈值（15px）后松手。

预期：两种方式均触发相同交换逻辑；拖拽越界（棋盘边缘）不报错；模式为管理员时点击应选中格子而非交换。

TC-05：连锁消除与连击

目标：多轮连锁消除可连续执行且计分稳定。

预期：comboCount 递增，多次消除连续执行，分数按连击倍数计算，无卡死或状态异常。

TC-06：爆炸规则（cross / screen / blast）

目标：按消除数量触发对应爆炸。

步骤：在管理员模式设置爆炸规则：4=cross、5=screen、6=blast:2，分别构造 4/5/6 连消除。

预期：4 连触发十字、5 连触发全屏、6 连触发半径 2 范围爆炸；被波及的可消除棋子被清除，围墙受损。

TC-07：炸弹棋子

目标：bomb 状态棋子参与消除时波及周围 3×3。

预期：炸弹所在格及其 8 邻域受影响，计分与状态更新正确。

TC-08：锁定棋子 locked

目标：locked 棋子不可交换且不可被消除。

预期：尝试交换被拒绝并提示；参与匹配或爆炸时该格保留。

TC-09：冰冻与冰层（frozen / ice）

目标：frozen 阻止交换；冰层（0-6）视觉与数值正确。

预期：frozen 棋子无法交换；ice 层级数字/透明度随等级变化，逻辑稳定无渲染异常。

TC-10：围墙破坏机制

目标：围墙 hp 随相邻消除/爆炸递减并最终移除。

步骤：在 wall 模板或单格编辑中配置带围墙棋子，通过相邻消除或爆炸造成伤害。

预期：HP 按规则减少，HP=0 后围墙消失；相邻格共享边不出现重复/错乱描边。

TC-11：时间限制

目标：计时归零后正确结算。

步骤：开启时间限制并设置短倒计时，切换到游戏模式等待耗尽。

预期：时间递减正确，到 0 结束并弹出结算（达成目标判胜，否则判负）。

TC-12：步数限制与胜负判定

目标：步数用尽后胜负判定与目标检查一致。

预期：每步递减 1；到 0 时若已达成通关目标判胜，否则判负；低步数时出现预警样式。

TC-13：通关目标（最低分 / 消除指定棋子）

目标：两种通关条件可单独或同时生效。

步骤：启用最低分 500 并设总步数 30；另启用"消除指定棋子 ×N"，分别验证。

预期：达成任一启用目标即触发胜利结算；HUD 目标区显示进度（如 A×10[3/10]）。

TC-14：模板切换

目标：classic/timed/challenge/wall 模板参数正确生效。

预期：棋盘尺寸、步数、时间、matchLength、田字/斜线开关随模板更新；挑战与围墙模板正确加载预设 initialBoard / 带墙棋子；应用后棋盘稳定无初始三连。

TC-15：配置保存与恢复

目标：配置保存、刷新恢复正常。

预期：保存后立即生效，刷新后仍保留（candy_crush_config_v5），无异常文本残留。

TC-16：初始棋盘配置

目标：自定义布局按定义重建。

步骤：在初始棋盘文本域输入含 empty / apple|frozen / grape|bomb / orange|locked 的布局并应用。

预期：empty 解析为空位，frozen/bomb/locked 状态按设置生效；未知类型不回退为随机棋子（保持空位）。

TC-17：配置字符串稳定性

目标：含 rgba 颜色、围墙、pattern 的配置不被错误拆分成棋盘文字。

预期：字段被正确解析，棋盘不出现配置片段/乱码，视觉层不叠加异常。

TC-18：管理员模式单格编辑

目标：右侧编辑器可精确修改单格属性。

步骤：管理员模式下点选一个格子，修改类型/图案/底色/图案色/可移动/冰层/四边围墙后点"应用到当前格子"。

预期：格子即时更新为新属性；"清空当前格子"可将该格置空；未选中格子时编辑器为空态。

TC-19：模式切换

目标：管理员/游戏模式切换行为正确。

预期：管理员模式可点选编辑、规则面板可见；游戏模式隐藏编辑面板、点击/拖拽只用于交换；切换游戏模式自动启动计时器（若启用）。

TC-20：关卡保存与加载

目标：关卡可保存入库并被重新加载。

步骤：填写关卡名称 → "保存为关卡"；在"已保存关卡"列表点击"加载"。

预期：关卡写入 candy_crush_levels_v5（上限 20，重名覆盖）；加载后棋盘与规则完整恢复；列表可正常刷新。

TC-21：提示与无解洗牌

目标：提示功能与无解自动重排正常。

步骤：点"提示"按钮观察高亮；用管理员工具构造无可行步盘面后走一步。

预期：提示高亮建议交换并在约 1.5s 后消失；若无可行步，游戏自动洗牌并稳定化，不卡死。

TC-22：语法与性能回归

目标：脚本无语法错误，消除动画流畅。

预期：node --check game.js 通过；长连击消除过程仅局部刷新，无整盘闪烁；控制台无异常报错。

6. 缺陷回归清单

  • 颜色/围墙配置被错误切割导致棋盘出现文字残留
  • 整盘重渲染导致视觉闪烁
  • 保存/模板切换后旧棋盘状态未清理造成失真
  • 特殊状态与围墙同步错误、相邻墙重复描边
  • 配置更新后 requiredPieceType 等旧引用未重置
  • 交换/消除过程中并发输入导致棋盘状态竞争
  • 初始棋盘无法识别类型时被随机棋子顶替

7. 测试结论

当以上测试用例全部通过时，说明项目具备稳定的双模式交互、完整的规则与目标结算、可靠的配置/关卡持久化，以及可持续扩展的设计基础。对原型级前端游戏而言已达到较成熟的演示与迭代水平。

交付判定：建议将该版本视为可演示、可评审、可扩展的前端游戏原型；后续扩展玩法时应优先补充自动化回归、配置校验与状态一致性测试。

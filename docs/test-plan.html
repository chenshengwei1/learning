糖果消消乐项目测试计划

1. 文档目的

本文档用于对糖果消消乐项目进行功能验证、回归检查和交付验收，覆盖核心玩法、配置能力、状态系统与浏览器表现。它适用于开发阶段检测和团队评审阶段确认。

2. 测试目标

  • 棋盘渲染与交互是否正常
  • 相邻交换与消除规则是否正确
  • 爆炸、围墙、冻结与锁定状态是否有效
  • 配置模板切换和本地保存是否稳定
  • 初始棋盘和时间限制逻辑是否符合预期
  • 局部刷新、状态重置和页面稳定性是否可靠

3. 测试范围

功能验证

  • 基础消除
  • 连锁响应
  • 计分逻辑
  • 步数控制
  • 时间限制
  • 胜负判断

配置验证

  • 模板切换
  • 自定义布局
  • 保存与恢复
  • 默认配置回退
  • 配置解析稳定性

特殊状态验证

  • locked
  • frozen
  • bomb
  • wall

4. 测试环境

运行环境

  • 浏览器：Chrome、Edge、Firefox 的现代版本
  • 运行方式：直接打开 index.html
  • 依赖项：无额外安装依赖

验收方式

  • 手动交互验证
  • 浏览器控制台检查报错
  • localStorage 检查配置持久化状态
  • 关键脚本运行语法检查：node --check game.js

5. 测试用例

TC-01：页面正常加载

目标：验证页面可以稳定初始化，并展示游戏主体内容。

步骤：打开 index.html，查看页面布局与状态区。

预期：页面总体结构正常，棋盘展示稳定，计分、步数和时间等状态可见，控制台无明显脚本错误。

TC-02：有效交换与消除

目标：验证相邻棋子合法交换后，能够形成匹配并消除。

预期：若形成 3 连及以上，棋子被移除，分数增加，重力补齐生效，UI 状态同步更新。

TC-03：无效交换

目标：验证不构成有效消除的交换不会造成错误结果。

预期：操作被拒绝、棋子位置恢复、无错误计分、页面状态保持一致。

TC-04：连锁消除

目标：验证多轮连锁消除仍然可执行，并保持分数逻辑稳定。

预期：连击数递增，多次消除连续执行，分数计算符合连锁规则，不出现卡死或状态异常。

TC-05：炸弹机制

目标：验证 bomb 状态在消除时会触发范围爆炸。

预期：周围格子被额外清除，爆炸区域明确，计分与状态更新正确。

TC-06：锁定棋子

目标：验证 locked 状态阻止交换行为。

预期：交换被拒绝，游戏提示清晰，不发生错误判定。

TC-07：冰冻棋子

目标：验证 frozen 状态不会破坏交互稳定性。

预期：无法执行交换，页面逻辑保持稳定，无渲染异常。

TC-08：围墙破坏

目标：验证围墙 hp 机制可正常减少并最终消失。

预期：围墙 HP 按规则减少，HP 为 0 后围墙移除，视觉层与逻辑层一致。

TC-09：时间限制

目标：验证计时功能能够在到时后结束游戏。

预期：时间递减持续正确，到 0 时结束游戏，结果和状态显示正常。

TC-10：步数限制

目标：验证步数机制和胜负判断一致。

预期：步数逐步递减，到达上限后结束游戏，不出现步数计算偏差。

TC-11：模板切换

目标：验证模板配置生效，并且规则与参数同步更新。

预期：棋盘大小、时间限制、步数等变化正确，相关 UI 区域同步更新。

TC-12：配置保存与恢复

目标：验证配置保存、重载和恢复功能正常。

预期：保存后配置生效，刷新后仍然保留配置，页面没有异常文本残留。

TC-13：初始棋盘配置

目标：验证自定义棋盘布局能够按要求重建。

预期：指定格子生成正确棋子，empty 能被正确解析为空，frozen、bomb、locked 等状态按设置生效。

TC-14：配置字符串稳定性

目标：验证颜色值和围墙字段不会因为字符串拆分而导致异常渲染。

预期：配置字段被正确解析，棋盘上不出现无意义字符串，视觉层没有异常丢失或叠加。

6. 缺陷回归清单

  • 颜色配置被错误切割导致棋盘出现文字残留
  • 整盘重渲染导致视觉闪烁
  • 保存后状态异常造成棋盘失真
  • 特殊状态与围墙同步错误
  • 配置更新后旧棋盘状态未清理

7. 测试结论

当以上测试用例全部通过时，说明项目具备稳定的交互能力、合理的规则逻辑和可持续扩展的配置设计。对于一个原型级前端游戏而言，它已经达到较成熟的演示与迭代基础。

交付判定：建议将该版本视为可演示、可评审、可扩展的前端游戏原型。

糖果消消乐项目设计说明

1. 文档定位

本文档为糖果消消乐项目的技术设计说明，面向项目交付、迭代评审和后续扩展维护。它用于说明该项目的设计思路、关键模块职责、规则引擎机制以及演进方向，适合团队在实现评审、方案沟通和后续二次开发时作为统一依据。

2. 项目概述

本项目是一个基于原生 HTML、CSS 和 JavaScript 开发的消消乐小游戏。它不依赖第三方前端框架，采用轻量化结构来实现棋盘渲染、规则判定、状态管理和配置化能力，突出展示“游戏玩法 + 可配置规则 + 可扩展架构”的实现思路。

2.1 当前能力

  • 经典邻接交换与连线消除
  • 横向、纵向、田字形及斜线匹配规则
  • 冰冻、锁定、炸弹等特殊状态机制
  • 单边围墙与耐久度设计
  • 时间限制和步数限制
  • 模板配置、棋盘预设和自定义布局
  • 本地存储配置持久化
  • 局部重绘与状态更新优化

2.2 设计目标

  1. 交互简单：玩家可直接在浏览器中体验完整基础玩法。
  2. 规则可配置：不同模板下可以切换玩法规则与参数。
  3. 架构可扩展：后续可加入更多道具、任务系统和更复杂的视觉层。
  4. 代码轻量：适合演示、教学、原型开发和功能快速迭代。

3. 架构设计

3.1 总体结构

项目结构以功能模块划分为主：

  • index.html：游戏页面和 UI 控件
  • style.css：棋盘样式、状态样式、层级样式
  • game.js：游戏核心逻辑，包含规则、状态和渲染控制
  • docs/：项目说明、测试计划和操作手册

3.2 核心模块

配置系统

配置模块是本项目的重要扩展点，负责统一维护默认规则参数、模板配置、棋盘尺寸、棋子类型、时间限制设置、初始布局定义以及本地缓存键。

关键对象包括：

  • DEFAULT_CONFIG：默认配置
  • PRESET_CONFIGS：预设模板
  • CONFIG_KEY：持久化键名

棋子对象模型

棋子使用统一的 Piece 结构表示，具备 id、type、color、pattern、state、walls 与 style 等信息。

匹配规则系统

规则系统通过统一的 MatchRule 结构执行判定，主要包括横向/纵向连续匹配、田字形判定、斜线判定，以及消除后的特殊效果处理。

爆炸与连锁系统

当等值匹配或特殊棋子触发时，系统会生成爆炸效果，影响相邻或范围内的格子，从而形成连锁扩展。

计分系统

分数模块负责统一处理基础消除分数、连击倍数加成、特殊块爆炸奖励和任务目标积分。

游戏主引擎

GameEngine 是整个流程的核心协调器，负责初始化棋盘、处理玩家交换、判定合法性、处理消除、重力、填充、计算分数与状态、更新 UI，以及判断胜负和结束条件。

4. 关键算法设计

4.1 棋盘表示

board[row][col] = Piece | null

这样可以高效完成规则扫描、重力计算、可交换判定和局部渲染更新。

4.2 匹配判定逻辑

对于每个规则，算法都会生成一个匹配集合，最后统一合并。这样做的优点是不同规则可以独立开发和测试，最终结果也可去重，避免重复消除。

4.3 重力下落算法

  1. 遍历每一列；
  2. 筛出非空棋子；
  3. 按底部优先位置回填；
  4. 空位填充新的棋子；
  5. 记录受影响格子并局部刷新。

4.4 围墙破坏机制

围墙设计为方向性、可损耗的结构。每个格子的四个方向可以分别配置围墙，分别是 top、right、bottom、left。

piece.walls[side] = { enabled, hp, maxHp, color }

当相邻格子发生消除或爆炸时，系统会对对应方向的围墙造成伤害。HP 为 0 后，围墙移除，提升玩法深度。

4.5 配置解析设计

该项目的配置解析逻辑是需要重点关注的核心风险区域。配置数据可能同时包含颜色字符串、规则参数、状态字段、围墙字段和初始棋盘布局，因此必须避免把颜色字符串或特殊配置值错误地拆分成多段内容，否则会造成“配置文本渲染进棋盘”的错误。

5. 状态管理设计

5.1 运行状态

  • isProcessing：是否正在执行交换或消除流程
  • isGameEnded：是否已结束
  • selected：当前选中棋子
  • lastHint：提示的建议交换

5.2 棋子状态

  • locked：锁定，不能交换
  • frozen：冻结，不能交换
  • bomb：爆炸，参与消除后触发范围破坏

6. 配置与持久化

localStorage.setItem(CONFIG_KEY, JSON.stringify(cfg));

保存内容包括棋盘规模、主题与色板配置、模板参数、游戏时间限制、初始棋盘布局和自定义规则。这使得用户在刷新页面或重新打开页面后，仍然能够保持当前的关卡和玩法设置。

7. 可扩展性设计

玩法扩展

  • 新增道具：交换器、横向清除、纵向清除、颜色炸弹
  • 新增任务目标：分数目标、步数目标、清除目标
  • 新增动态事件：随机掉落、卡片效果、机关格子

视觉扩展

  • 底色与图案层分离
  • 冰冻、护盾和封印层分离
  • 围墙支撑层与边框层独立渲染
  • 着色动画、粒子效果和更丰富的状态反馈

8. 关键风险与工程注意事项

  1. 配置解析风险：颜色字符串、围墙字段和状态字段易发生误拆分。
  2. 重渲染成本：若每次消除都整盘渲染会造成性能和视觉问题。
  3. 连锁逻辑复杂性：需多轮循环检测和状态同步。
  4. 状态脏数据问题：配置修改后若未重置旧状态，棋盘容易出现残留异常。

9. 设计结论

本项目的设计重点不是追求框架的复杂度，而是突出“玩法清晰、架构可扩展、配置灵活、可演示”的工程价值。它具备较好的教学展示性质，也为后续发展为更完整的消消乐产品原型提供了坚实的基础。

交付建议：后续优先推进道具扩展、关卡任务和自动化回归测试，使该项目从演示型原型逐步升级为更成熟的产品级实现。
